IELTS-style Reading Banks / 雅思式阅读题库

Two extra fields — section and passage — turn an ordinary bank into a reading test: each passage is shown once, followed by its own questions, in order. Everything else on the main format page still applies.

English

What the two fields do

FieldWhere it goesEffect
sectionOn every question of a passage, spelled identicallyGroups the questions under a heading. The heading is printed once, above the first question of the group.
passageOn the first question of each sectionRenders a collapsible “📖 Reading Passage” box (open by default) above that section’s questions. Blank line = new paragraph; a single newline = line break.

What changes once any question has a section

  • Questions are never shuffled. The array order is the reading order, so every passage stays with its own questions. The Randomize + Reset button is therefore relabelled Retest — it clears this round’s answers and keeps the order.
  • The filter panel lists passages instead of id prefixes, so you can practice one passage at a time.
  • Everything else is unchanged: wrong-only / starred-only views, the answer sheet, progress saving, and per-question explanation all work the same.

Rules worth getting right

  • The section string is the group key — it must be byte-identical across a passage’s questions. "Passage 1" and "Passage 1 " become two groups.
  • Only the first question of a section is read for passage. Repeating it on later questions is harmless but pointless; putting a different text there silently does nothing.
  • section and passage are plain text — HTML in them is escaped and shown literally, not rendered. Use blank lines for paragraphs.
  • Don’t mix: give every question a section. One sectioned question is enough to stop the whole bank from shuffling, and the un-sectioned ones then fall back to grouping by id prefix — a confusing mix in the filter panel.
  • A long passage repeated as a paragraph inside question instead of passage will still work, but it shows once per question and can’t be collapsed.

Mapping IELTS task types onto the three supported shapes

IELTS taskWrite it as
Multiple choice (one answer)choices + answer (0-based index)
Choose TWO / THREEchoices + answers: [0,2] — checkboxes, exact set required
True / False / Not Givenchoices: ["True","False","Not Given"] + answer. Yes/No/Not Given: use ["Yes","No","Not Given"] — keep the test’s own wording so the distinction is preserved.
Matching headings / features / sentence endingsOne question per item; choices = the whole list offered; answer = the right index. (Re-listing the full option set on each item is what makes each one answerable on its own.)
Sentence / summary / note / table / flow-chart completion, short answertype:"fill" + blanks, one array per blank listing every accepted answer. Use question_html with <input data-blank="1"> to place the boxes inside the sentence; omit it and the boxes appear under the stem.
Diagram / map / plan labellingSame as completion, plus image.
Writing / speaking tasksNot supported — there is nothing to grade. type:"essay" displays but is dropped on import.

Word limits and accepted answers

  • Keep the instruction (“NO MORE THAN TWO WORDS AND/OR A NUMBER”) in the question text — the player does not enforce it, so the learner needs to see it.
  • List every equally-correct form in that blank’s array: singular and plural, a hyphenated and spaced variant, a number and its word. Grading already ignores case, extra spaces, spacing (check list = checklist), curly quotes/dashes and a trailing full stop.
  • Use answer_sets when blanks are only correct in combination — e.g. two blanks that may be filled in either order. Each set lists one acceptable value per blank; any one matching set is correct.

Explanations earn their keep here

IELTS reading is won on where the answer is, so explanation is worth more than in an ordinary bank. Name the paragraph and quote the handful of words that decide it — that is exactly what turns a wrong True/False/Not Given into a lesson:

"explanation": "Paragraph 2 places glass blowing on the Syro-Palestinian coast, not Egypt — the passage contradicts the statement, so False (not Not Given)."

The reveal is gated: after submitting, the learner taps Show Correct Answers and the 💡 explanation appears together with the correct answer. Because both sit behind the same gate, a full set of explanations can never spoil a first attempt. / 揭示是有闸的：提交后点「Show Correct Answers」，💡 解析与正确答案一起出现——两者共用同一道闸，所以写满解析也不会毁掉第一次作答。

BATCHES (important — free ChatGPT/Gemini cut long replies off): do ONE passage per reply, and at most 15 questions. End the reply with the line MORE AVAILABLE if a passage is still left, otherwise DONE. When I type "more", do the next passage in the same format.

GROUPING — this is what makes it a reading bank:
- Every question gets "section": the passage title, written IDENTICALLY for every question of that passage. Same wording and spacing every time — one typo splits the passage in two.
- The FIRST question of each passage also gets "passage": the full reading text, paragraphs separated by a blank line. Do not repeat it on the other questions, and do not shorten or summarise it.
- Keep the questions in the order the test asks them.

TASK TYPES
- Multiple choice: "choices" + "answer" = 0-based index (a plain integer).
- Choose TWO/THREE: "choices" + plural "answers" = [0,2].
- True/False/Not Given: "choices":["True","False","Not Given"]. Yes/No/Not Given: ["Yes","No","Not Given"]. Keep the test's own wording.
- Matching headings/features: one question per item, "choices" = the whole list of options offered, "answer" = the right index.
- Any completion or short answer: "type":"fill" + "blanks" = one array per blank listing every accepted answer (include plurals and equally correct wordings). Respect the word limit stated in the test.
- Diagram labelling: same as completion, plus "image" if a picture is given.
- Writing/speaking tasks: skip them, they cannot be graded.

Optional and very useful: "explanation" — one sentence naming the paragraph and quoting the few words that prove the answer.

Straight ASCII quotes. No trailing commas. Do not wrap the array in an object. A sentence before the JSON or a code block around it is fine — the importer strips those.

中文

两个额外字段 section 和 passage 就能把普通题库变成阅读测试：每篇文章只显示一次，后面紧跟它自己的题目，按原顺序作答。主格式页的其他规则照旧适用。

  • section：每一道属于这篇的题都要写，且写法必须完全一致（多一个空格就会拆成两组）。它是分组键，篇名只在该组第一题上方打印一次。
  • passage：只放在每篇的第一题上，渲染成可折叠的「📖 阅读文章」框（默认展开）。空行分段，单个换行 = 换行。放在后面的题上不起作用。
  • 两个字段都是纯文本，写 HTML 会被转义原样显示，不会渲染。
  • 只要有一道题带 section，整个题库就不再打乱（保证文章与题目不脱节），「Randomize + Reset」按钮改叫「Retest」＝只清空本轮作答、不改顺序；筛选面板也从「按 id 前缀」变成「按篇」，可以一篇一篇练。
  • 别混着写：给每道题都加 section。漏掉的那些会退回按 id 前缀分组，筛选面板会出现两套口径。

雅思题型 → 三种可判分题型

  • 单选 → choices + answer（下标从 0 开始）
  • Choose TWO/THREE → choices + answers:[0,2]（自动变复选框，需全对）
  • True/False/Not Given → choices:["True","False","Not Given"] + answer；Yes/No/Not Given 用 ["Yes","No","Not Given"]，按原卷用词，别混用
  • Matching headings / features / endings → 每个小题一条记录，choices 放完整选项表，answer 指向正确项
  • 各类 completion / 短答 → type:"fill" + blanks（每空一个数组，列出所有可接受写法：单复数、连字符/空格、数字与英文）；想把输入框放进句子中间就用 question_html 配 <input data-blank="1">
  • 图/地图标注 → 同 completion，再加 image
  • 写作/口语 → 不支持（无从判分）；type:"essay" 能显示但导入时会被剔除
  • 字数限制（NO MORE THAN TWO WORDS）播放器不强制，务必把这句话留在题干里让人看见；同时确认 blanks 里列的每个写法都符合限制
  • 两个空只有组合起来才算对（如可互换顺序）→ 用 answer_sets，每组给出各空一个值，任一组全中即对
